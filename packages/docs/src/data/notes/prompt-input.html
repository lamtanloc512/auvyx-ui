Without JavaScript the form submits like any form. Load js/prompt-input.min.js (not part of auvyx.min.js) for the chat behavior; rendering replies and streaming them stay with your app.

HTML structure

<auvyx-prompt-input> around <form class="prompt-input">
Add the streaming attribute while a reply streams: Stop replaces Send. Add busy instead for work that cannot be stopped (uploading, indexing): the field, Send and the attach button are disabled, Enter does nothing, the form gets aria-busy="true" and data-state="busy" for your CSS. data-variant="raised" on the form gives a card-like composer with a soft shadow, for a prompt that is the center of a page.
<textarea>
Grows with its content (CSS field-sizing). Enter sends, Shift+Enter adds a line.
<div class="attachment-group" data-files hidden> Optional
Files from the picker, a drop or a paste are listed here as .attachment items with a remove button.
<footer>
Toolbar. [data-attach] opens the <input type="file" hidden>; [type="submit"] sends and is disabled while empty or busy; [data-stop] shows while streaming.
<small> or [data-hint] Optional
Helper text. First in the footer, it lines up with the prompt text and takes the free space.
<span data-busy> Optional
Shown only while busy, for a spinner and a word on what is happening.
.suggestions inside the element Optional
Before or after the form (it gets a margin on the side facing the form). A click fills the prompt with the chip's data-prompt or text; data-send sends it straight away.

JavaScript API

API Type Description
prompt Event Cancelable. detail: { text, files } when the user sends. The field clears unless you call preventDefault().
stop Event The user pressed Stop while streaming.
el.streaming Property Mirrors the streaming attribute.
el.busy Property Mirrors the busy attribute.
el.value Property The prompt text.
