# Plan: shadcn-svelte–style foundation and premium blocks

Target: the same foundation shape as shadcn-svelte (one docs app, registry served as JSON, a CLI that copies open code into the user's project, blocks gallery), with a paid block tier distributed through an authenticated registry.

## Current state

| Area | Today | shadcn-svelte equivalent |
| --- | --- | --- |
| Core CSS/JS | `src/` (upstream Basecoat, `basecoat-css`) and `packages/ui` (`@auvyx/ui`, built from `src/` + `src/css/extra`) | `packages/` + registry `ui` items |
| Behavior | `src/js/*` and `packages/elements` (custom elements) | Svelte components |
| Blocks | `packages/blocks/*.html` generated by `packages/blocks/tools/*.py`, metadata in `registry.json` | `registry/blocks` |
| Docs | Two apps: `site/` (Astro, Basecoat docs) and `packages/docs` (static, Auvyx docs + blocks gallery + Create page) | One SvelteKit app |
| Registry | **Added:** `packages/blocks/tools/build_registry.mjs` → `r/<name>.json`, served by `packages/docs` at `/r/` | `/registry/*.json` |
| CLI | **Added:** `packages/cli` (`init`, `add`, `list`, namespaced + authenticated registries) | `shadcn-svelte` CLI |

## Phases

### 1. Foundation (started)

- [x] Registry build for blocks (free tier) with fragment + standalone page per item.
- [x] CLI with namespaced registries, `${ENV}` headers for license keys, path-traversal guard.
- [ ] Registry items for components (`registry:ui`), so `add` can install component CSS/JS, not only blocks.
- [ ] Workspaces: root `package.json` `workspaces: ["packages/*", "site"]`, one `npm run build` for ui → elements → blocks → registry → docs.
- [ ] CI: build + `scripts/check.js` + Playwright smoke tests on `packages/ui/preview.html` and block pages.
- [ ] Port block generators from Python to Node so the toolchain is one runtime.

### 2. One docs app

- [ ] Pick one docs app (see open questions) and move the other's content into it.
- [ ] Pages: Docs, Components, Blocks (iframe preview + code tabs + `npx @auvyx/cli add` command), Charts, Themes/Create, Pricing.
- [ ] Block pages show tier; pro blocks show a screenshot/live preview but no source.

### 3. Premium tier

- [ ] Private repo (e.g. `auvyx-pro`) with pro block sources; reuse `build_registry.mjs --src … --tier pro`.
- [ ] Authenticated registry endpoint: validates `Authorization: Bearer <license>` and serves `r/<name>.json` (Cloudflare Worker + KV/R2 fits the existing `wrangler` setup in `site/`).
- [ ] Payments + license issuing (Stripe Checkout or Lemon Squeezy → webhook → license key in KV; email the key).
- [ ] License terms for pro blocks (per-developer / team / unlimited projects); free tier stays MIT.
- [ ] Download ZIP fallback for users who don't use the CLI.

### 4. Product

- [ ] Pro block catalog that is not a copy of free shadcn blocks: marketing (hero, pricing, features, testimonials, footer), app shells, dashboards, settings, data-table pages, onboarding, e-commerce.
- [ ] Framework snippets for each block: plain HTML, Nunjucks/Jinja macros, and later Laravel Blade / Django / Rails partials (the stacks a non-React kit sells to).

## Risks

- **Pro source in a public repo leaks.** This repo is a public fork; pro blocks must live in a private repo and only ship through the authenticated registry.
- **Free blocks are ports of shadcn/ui blocks** (`login-*`, `sidebar-*`, `calendar-*`, `dashboard-01`). shadcn/ui is MIT, so they are fine as free items, but they are weak as paid value.
- **Licensing.** Basecoat (MIT, Ronan Berder) must keep its copyright notice in `LICENSE.md` and published packages.
- **Two brands, two packages** (`basecoat-css` and `@auvyx/ui`) confuse buyers; pick one public name.
- A bearer key in the CLI can be shared. Mitigate with per-key rate limits and seat checks, not DRM.

## Open questions

2. Brand and npm scope: `@auvyx/*` only, or keep publishing `basecoat-css`?
3. Domain for the docs site and the pro registry (`init` currently requires `--registry`).
4. Payment provider and license model.
